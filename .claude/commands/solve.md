코딩 문제의 풀이를 단계적으로 안내해주세요. 한 번에 정답을 보여주지 않고,
**힌트 → 접근법 → 풀이** 순으로 사용자가 스스로 생각할 기회를 줍니다.

## 입력
$ARGUMENTS

인수로 주어지는 것:
- 문제 설명 (직접 붙여넣기)
- 백준/프로그래머스/LeetCode/AtCoder 문제 번호 (예: `백준 1920`, `LC 1`, `ABC 300 C`)
- 특정 유형 요청 (예: `BFS 문제 하나`)

## 풀이 가이드 진행 (4단계)

### 1단계: 문제 분석 (즉시 제공)
- 문제를 정리하여 재서술
- 입출력 분석
- 제약 조건에서 유추할 수 있는 시간 복잡도 힌트
  - N ≤ 10 → O(N!) 가능 (완전탐색/백트래킹)
  - N ≤ 20 → O(2^N) 가능 (비트마스킹)
  - N ≤ 100 → O(N³) 가능
  - N ≤ 1,000 → O(N²) 가능
  - N ≤ 100,000 → O(N log N) 필요
  - N ≤ 10,000,000 → O(N) 필요

### 2단계: 힌트 (사용자 요청 시)
- 「힌트 주세요」라고 하면 제공
- 사용할 자료구조 또는 알고리즘 패턴을 **간접적으로** 암시
- 예: 「정렬 후 특정 조건으로 탐색하면 어떨까요?」
- 정답을 직접 알려주지 않음

### 3단계: 접근법 (사용자 요청 시)
- 「접근법 알려주세요」라고 하면 제공
- 구체적인 알고리즘 선택과 이유
- 핵심 아이디어를 의사코드 수준으로 설명
- 아직 완전한 코드는 제공하지 않음

### 4단계: 전체 풀이 (사용자 요청 시 또는 사용자 코드 제출 후)
- 완전한 Python 풀이 코드 (한국어 주석 포함)
- 브루트포스 → 최적화 순서로 2가지 풀이 제시 (가능한 경우)
- 시간/공간 복잡도 분석
- 엣지 케이스 목록

## 풀이 후 처리

1. `docs/records.md`를 Read하여 포맷 확인 후 `progress/solve-log.md`에 기록
2. 관련 패턴을 `notes/`에 추기
3. 자력으로 풀었으면 → `progress/topics.md` `[x]` 업데이트
4. 풀이를 참고했으면 → `progress/topics.md` `[~]` 유지 + 유사 문제 추천
5. 풀이 코드를 `solutions/` 해당 카테고리에 저장

## 규칙
- **절대 1단계에서 바로 정답 코드를 보여주지 않는다**
- 사용자가 직접 시도할 시간을 충분히 준다
- 사용자 코드에 버그가 있으면, 버그 위치만 힌트를 주고 스스로 고치게 유도
